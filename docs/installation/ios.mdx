# Install on iOS

## Minimum deployment target

In order to use the `location` plugin, you need to set your minimum deployment
target to iOS 13.0 or later:

```ruby name="ios/Podfile"
platform :ios, '13.0'
```

## Info.plist

In order to request location permissions, you need to add the following to your
`ios/Runner/Info.plist`:

```
<key>NSLocationWhenInUseUsageDescription</key>
<string>The app needs the location</string>
```

The string will appear in the popup when the user is asked to grant location
permissions.

## Background location

On iOS the plugin only ever requests **When In Use** authorization, and that is
enough to keep receiving updates in the background once you call
`enableBackgroundMode(enable: true)`. iOS shows a blue location indicator in the
status bar while it does.

To allow it, enable the background mode for the **Runner** target. Open Xcode and
go to "Signing & Capabilities". Add the "Background Modes" section and add
"Location updates" to the list.

You don't need `NSLocationAlwaysAndWhenInUseUsageDescription` for this. Add it
only if your app requests **Always** authorization itself, for example through
another package:

```
<key>NSLocationAlwaysAndWhenInUseUsageDescription</key>
<string>The app needs the location</string>
```

The plugin never references `requestAlwaysAuthorization` on iOS, so App Store
Connect doesn't ask for this key (ITMS-90683) when your app only declares
`NSLocationWhenInUseUsageDescription`.
